## 🐛 Bug 1 — Infinite Page Reload Loop
**File:** `frontend/src/api/axiosInstance.js`

### What was the problem?
You had an Axios **interceptor**. An interceptor is a piece of code that watches every single API request/response across your whole app. If any response comes back with an error, this interceptor runs automatically.

The interceptor said:
> "If I get a **401** (not logged in) OR a **404** (not found) error → send the user to `/login`"

The problem is: **404 means something wasn't found**, not that the user is unauthorized. So if any API call returned 404, the user got kicked to the login page — even if they were already logged in!

And worse — even **on the `/login` page itself**, the app was still making API calls (like fetching songs from `MusicContext`). Those calls could fail → interceptor kicks in → redirects to `/login` → page loads again → more API calls → fail again → redirect again → **forever**.

### What was the fix?

```js
// ❌ BEFORE (broken)
if (error.response?.status === 401 || error.response?.status === 404) {
    window.location.href = "/login";
}

// ✅ AFTER (fixed)
const isOnAuthPage = window.location.pathname === "/login" || window.location.pathname === "/author-login";
if (error.response?.status === 401 && !isOnAuthPage) {
    window.location.href = "/login";
}
```

**Two things changed:**
1. **Removed 404 from the condition.** Only 401 (unauthorized) should redirect to login. 404 is not a "you need to log in" error.
2. **Added a guard: `!isOnAuthPage`.** If you are already on the login page, don't redirect to login again. This breaks the infinite loop.

## 🐛 Bug 2 — `isCurrentSongPlaying` was `undefined`
**File:** `frontend/src/pages/MusicPlay.jsx` and `frontend/src/store/features/player/playerSlice.js`

### What was the problem?

In Redux (your global state manager), the **playerSlice** defines:
- A **state** (the actual data stored)
- **Reducers** (functions to change that data, also called actions)

In `playerSlice.js`, the state and the reducer have **different names**:

```js
initialState: {
    isPlaying: false,      // <- this is the STATE field (the actual data)
},
reducers: {
    isSongPlaying: (state, action) => {   // <- this is the REDUCER (a function)
        state.isPlaying = action.payload;
    }
}
```

In `MusicPlay.jsx`, the code was reading:
```js
// ❌ WRONG — reading the reducer name, not the state field
const isCurrentSongPlaying = useSelector((state) => state.player.isSongPlaying);
```

`state.player.isSongPlaying` **does not exist** as a value in the state. It is the name of a function (reducer). So it came back as `undefined`.

### What was the fix?

```js
// ✅ CORRECT — reading the actual state field
const isCurrentSongPlaying = useSelector((state) => state.player.isPlaying);
```

**Simple rule to remember:**
- To **read** data from Redux → use `useSelector` with the **state field name** (`isPlaying`)
- To **change** data in Redux → use `dispatch` with the **reducer/action name** (`isSongPlaying(true)`)

## 🎵 Feature — Real Audio Playback & Progress Bar
**File:** `frontend/src/pages/MusicPlay.jsx`

### What existed before?
The MusicPlay page was **just a UI**. It had:
- A play/pause button (but clicking it did nothing to audio)
- A progress bar stuck at `w-1/3` (hardcoded 33%)
- Timestamps hardcoded as `1:26` and `3:21`

Nothing was actually playing any sound.

---

### Step 1 — The `<audio>` element

```jsx
<audio
    ref={audioRef}
    src={currentSongPlaying?.musicURI}
    onTimeUpdate={(e) => setCurrentTime(e.target.currentTime)}
    onLoadedMetadata={(e) => setDuration(e.target.duration)}
/>
```

**What is this?**
An `<audio>` tag is the browser's built-in music player. Without it, there is no sound — ever. It is invisible on screen (no `controls` attribute), but it runs in the background playing the song.

- `src={currentSongPlaying?.musicURI}` — tells the audio element which song file to load. `musicURI` is the field from your MongoDB database that stores the audio file URL.
- `ref={audioRef}` — gives us a **direct handle** to this element in JavaScript, so we can call `.play()` and `.pause()` on it later.
- `onTimeUpdate` — the browser fires this event about 4 times every second while the song plays. Every time it fires, we save the current time into state.
- `onLoadedMetadata` — fires once, right when the audio file finishes loading its info. At that point we know the total duration, and we save it.

---

### Step 2 — `useRef` for the audio element

```js
const audioRef = useRef(null);
```

**What is `useRef`?**
Think of it like a sticky note that lets you grab hold of an actual HTML element and control it directly from JavaScript.

Without `audioRef`, you would have no way to tell the audio element to play or pause. You would just have an `<audio>` tag floating there that you cannot control.

---

### Step 3 — `useState` for time tracking

```js
const [currentTime, setCurrentTime] = useState(0);
const [duration, setDuration] = useState(0);
```

**What is this?**
These are two pieces of local state:
- `currentTime` — how many seconds into the song are we right now? (starts at 0)
- `duration` — how long is the whole song in seconds? (starts at 0, gets set when audio loads)

Every time `onTimeUpdate` fires, we call `setCurrentTime(...)` which updates the value and causes the progress bar to re-render.

---

### Step 4 — `useEffect` to play/pause

```js
useEffect(() => {
    if (!audioRef.current) return;
    if (isCurrentSongPlaying) {
        audioRef.current.play();
    } else {
        audioRef.current.pause();
    }
}, [isCurrentSongPlaying]);
```

**What is this?**
Redux stores a boolean (`isPlaying: true/false`). But Redux does not know about the `<audio>` element — they do not talk to each other automatically.

This `useEffect` watches the Redux `isCurrentSongPlaying` value. Whenever it changes:
- If it becomes `true` — tell the audio element to `.play()`
- If it becomes `false` — tell the audio element to `.pause()`

The `if (!audioRef.current) return;` at the top is a safety check. It means: "if the audio element hasn't loaded yet, don't do anything."

**Why `useEffect` and not just call `.play()` directly?**
Because in React, you cannot directly control DOM elements while rendering. `useEffect` runs *after* the component has rendered, which is the right time to do side effects like playing audio.

---

### Step 5 — Progress bar percentage

```js
const progressPercent = duration ? (currentTime / duration) * 100 : 0;
```

**What is this?**
Simple math:
- `currentTime / duration` — gives a number between 0 and 1 (e.g. 0.33 means 33% through)
- `* 100` — converts it to a percentage (e.g. 33)
- The `duration ?` at the start is a safety check — if duration is 0 (song not loaded yet), return 0 instead of dividing by zero

This percentage is then used as the width of the green bar:
```jsx
style={{ width: `${progressPercent}%` }}
```

---

### Step 6 — `formatTime` function

```js
const formatTime = (secs) => {
    if (!secs || isNaN(secs)) return '0:00';
    const m = Math.floor(secs / 60);
    const s = Math.floor(secs % 60).toString().padStart(2, '0');
    return `${m}:${s}`;
};
```

**What is this?**
The browser gives us time in raw **seconds** (e.g. `86.5` seconds). But you want to show `1:26` on screen, not `86.5`.

- `Math.floor(secs / 60)` — gets the minutes (86 / 60 = 1.43, floor = 1)
- `secs % 60` — gets the leftover seconds (86 % 60 = 26)
- `.padStart(2, '0')` — makes sure it is always 2 digits (e.g. `5` becomes `05`)
- `if (!secs || isNaN(secs)) return '0:00'` — safety check for when the audio has not loaded yet

---

### Step 7 — Clickable progress bar (seeking)

```jsx
onClick={(e) => {
    if (!audioRef.current || !duration) return;
    const rect = e.currentTarget.getBoundingClientRect();
    const clickX = e.clientX - rect.left;
    const newTime = (clickX / rect.width) * duration;
    audioRef.current.currentTime = newTime;
    setCurrentTime(newTime);
}}
```

**What is this?**
This lets you click anywhere on the progress bar to jump to that point in the song.

- `getBoundingClientRect()` — gets the exact position and size of the progress bar on screen
- `e.clientX - rect.left` — how many pixels from the left edge of the bar did you click?
- `(clickX / rect.width) * duration` — converts that pixel position to a time in seconds
- `audioRef.current.currentTime = newTime` — jumps the audio to that point
- `setCurrentTime(newTime)` — updates the bar visually right away (instead of waiting for the next `onTimeUpdate`)
