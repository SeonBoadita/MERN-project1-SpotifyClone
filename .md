# HOW WE BLOCK LOGGED-IN USERS FROM `/login` (The PublicRoute Flow)

This is the step-by-step flow of how the code prevents a logged-in user from seeing the login page if they type `/login` in the URL.

### 1. The Starting Point: `main.jsx`

The entire app is wrapped in `<AuthProvider>`.
This is crucial because it ensures the authentication state (`isAuthenticated`) is shared globally across every single component in the application.

### 2. The State Manager: `AuthContext.jsx`

When the application first loads:

- `useEffect` immediately triggers the `checkAuth()` function.
- It pings the backend (`GET /auth/api/check`) to see if the HTTP-only cookie is present and valid.
- If valid, it sets `isAuthenticated = true` and `loading = false`.

### 3. The Router: `App.jsx`

Look at how the login route is defined:

```jsx
<Route path="/login" element={<PublicRoute><Auth /></PublicRoute>} />
```

Instead of rendering the `<Auth />` component directly when the user visits `/login`, React Router first renders the `<PublicRoute>` wrapper component, passing `<Auth />` inside it as a "child" component.

### 4. The Bouncer: `PublicRoute.jsx`

This is where the actual blocking happens. This component reads `isAuthenticated` and `loading` from the `AuthContext` and acts based on three conditions:

1. **If `loading` is true:**
   It returns a black screen that says "Loading...". This is important! Without this, the login page would flash on the screen for half a second while we wait for the backend's answer.

2. **If `isAuthenticated` is true:**
   It executes `return <Navigate to="/" replace />;`. This tells React Router to instantly redirect the user back to the Home page. Because of this `return` statement, the `<Auth />` component is completely ignored and never rendered on the screen!

3. **If `isAuthenticated` is false:**
   It executes `return children;`. The `children` prop represents the `<Auth />` component we passed inside it over in `App.jsx`. This tells React to go ahead and render the login form normally.
